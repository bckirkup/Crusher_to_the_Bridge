# Paper 3 campaign designs (`vs*` manifests)

> **Status:** Designs implemented, campaigns gated

Five campaign manifests implement the designs in
`variant_surveillance_plan.md` §6. They live beside the existing campaigns
in `picard_framework/runs/mega_cruise_campaign/` and are generated by the
`vs*` tier family in `variant_campaign.py`.

| `paper3_variant_emergence_v1_manifest.json` | variant emergence (real pathogens) | 2000 |
| `paper3_federation_patrol_v1_manifest.json` | Federation patrol (fictional) | 996 |

For scale: the mega cruise campaign is ~17,780 runs, so all five Paper 3
designs together are under half of it.

## Every run declares its data-generating process

The clock bug (`../history/epoch_time_unit_audit.md`) and the incubation change
(#290) both altered the generating model without altering any run id, which is
how two incompatible models can end up averaged in one results directory. So
each `vs*` manifest **must** declare a `natural_history_clock`, each tier
resolves an `incubation_arm`, and both appear in the run id:

```
vs1_diversity_hrs_dist_norovirus_classic_cruise_1900_d7_f1_inv_moderate_s900
             ^^^ ^^^^
             clock arm   incubation arm
```

Consequences, all covered by `../../tests/test_paper3_variant_campaigns.py`:

- `hours` runs are `_hrs_`, `legacy_epoch_day` runs are `_legacy_`, so the two
  arms cannot collide in one output directory or S3 prefix even by accident.
- `--natural-history-clock` disagreeing with the manifest is a hard error
  rather than a resolved precedence rule.
- All five designs are `hours`. `legacy_epoch_day` remains available only for
  reproducing pre-#303 results; no new legacy arm is submitted.
- The `fixed_onset` arm is not a label: the generated spec ships the pathogen
  profile with its `incubation` block removed, i.e. the pre-#290 process. A
  profile that never had one is refused, since the "control" would change
  nothing.

## Axes

`voyage_days` is the campaign-facing knob; epochs are derived from the
manifest's `epoch_duration_hours` (never a literal 24), so 7 days is 168
one-hour epochs. Remaining axes: `platforms`, `founder_strains`,
`mutation_rates`, `within_host_mutation_rates`, `recombination_rates`,
`superinfection_susceptibilities`, `surveillance_strategies`, `seeds`. Rate
axes patch the pathogen's `strain_evolution` block and leave the rest of the
profile alone.

Regimes, per the plan:

- **diversity** — multi-genotype embarkation, 1–4 founders, nominal
  per-pathogen rates.
- **emergence** — single founder, per-transmission and within-host mutation
  rate swept over ~2 decades around nominal.
- **interference** — `superinfection_susceptibility` sensitivity tier.
- **recombination** — `recombination_rate` sensitivity tier.
- **investment** — the four surveillance tiers (baseline / minimal / moderate /
  full) for the economics frontier.

Diversity, emergence and both sensitivity tiers are crossed with voyage length.

## Provisional numbers

Every tier is `deferred: true`: `--tier all` will not sweep them up, because
absolute counts and detection times ride on the `c1_*` `dose_adjustment` re-fit
under the hourly clock, which has not landed. What is quotable before it does
is comparative — arm against arm, tier against tier at fixed dose.

The two Starfleet designs are fictional in their parameters and their port
surveillance gradient; nothing from them is a measured capability. Fleet
network value pools independent single-ship runs at analysis time — there is no
new engine coupling. Investment optimization feeds
`../../picard_framework/analysis/economics`, whose valuation rates are still
placeholders.

## Sizing and running

```bash
# arithmetic count, generator-aware for sr*/vd*/vs*
python3 picard_framework/runs/mega_cruise_campaign/count_manifest_cartesian.py \
  picard_framework/runs/mega_cruise_campaign/paper3_variant_emergence_v1_manifest.json

# one tier, few runs, locally
python3 picard_framework/runs/mega_cruise_campaign/campaign_runner.py \
  --manifest picard_framework/runs/mega_cruise_campaign/paper3_variant_emergence_v1_manifest.json \
  --tier vs1_diversity_norovirus --limit 4 --epochs 48 --num-agents 150 \
  --output-dir telemetry_buffer/vs_smoke
```

`campaign_parameters` on each spec carries `regime`, `incubation_arm`,
`natural_history_clock`, `voyage_days`, `founder_strains` and the swept rate,
so an analysis can group by arm without re-parsing run ids.
